# `src/sanity/`

Everything for talking to Sanity from this app. Content itself is managed in Sanity, not this repo — edit it at `/admin` (locally: `http://localhost:3000/admin`). See [`docs/sanity.md`](../../docs/sanity.md) for environment setup, type generation, Studio navigation, and the walkthrough for wiring up a new page or section.

## Layout

- `client.ts` — the build-time Sanity client (`useCdn: true`), used by every `page.tsx` for its `client.fetch(...)` call.
- `env.ts` — required env vars (`NEXT_PUBLIC_SANITY_PROJECT_ID`, `NEXT_PUBLIC_SANITY_DATASET`, `NEXT_PUBLIC_SANITY_API_VERSION`), asserted at import time.
- `image.ts` — `urlForImage`, the image URL builder for Sanity image assets.
- `queries.ts` — every GROQ query (`defineQuery`), one per page document. Don't inline GROQ strings in components.
- `types.ts` — generated by `pnpm typegen` from the schema + queries above. Import result types from here (`HomePageQueryResult`, etc.) rather than hand-writing duplicates.
- `schemaTypes/` — the content schema.
- `structure.ts` — Studio's desk structure (nav for singleton documents). A schema type isn't visible in Studio until it has an entry here.
- `tools/` — custom Studio tool tabs (e.g. `DeploymentStatusTool.tsx`, which shows the latest Sanity-triggered deploy per environment).
- `lib/` — supporting code for the above (e.g. `deployStatus.ts`, which reads GitHub Actions' status for the deploy tool).
- `live/` — self-contained live-content feature: publish updates and editor-only draft previews on the public site with no rebuild. See [`live/README.md`](live/README.md).

## Environment variables

Required in `.env.local` for local dev:

```
NEXT_PUBLIC_SANITY_PROJECT_ID=k9mbvitn
NEXT_PUBLIC_SANITY_DATASET=development
NEXT_PUBLIC_SANITY_API_VERSION=2026-01-01
```

Dev and production are separate Sanity datasets (`development` and `production`) with independent content — see [`docs/deploy-krystal.md`](../../docs/deploy-krystal.md).
